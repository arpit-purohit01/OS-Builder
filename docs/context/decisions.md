# Architecture Decision Records

Format: Context → Decision → Consequences → Revisit when.

## ADR-0001 Build on an upstream distribution, never a custom kernel/userland
- Context: users want "their own OS" but cannot maintain a kernel or package archive.
- Decision: compose images from a pinned upstream base (Debian 13 first). Custom kernels only as config fragments on the base's kernel source in Expert mode (Phase 6).
- Consequences: security updates come from upstream; our job is composition, signing, delivery.

## ADR-0002 mkosi as the image build engine
- Context: options are live-build, debootstrap scripts, KIWI, Buildroot/Yocto, NixOS, mkosi.
- Decision: mkosi (pinned release). It supports Debian/Ubuntu/Fedora/Arch, produces GPT disk images via systemd-repart, UKIs, verity, sysext, Secure Boot signing and reproducibility knobs.
- Consequences: one engine for all bases; we track mkosi releases closely; config generated by our compiler, never hand-edited per customer.
- Revisit when: embedded/IoT targets need Yocto-level minimal images.

## ADR-0003 Image-based immutable /usr with A/B slots
- Decision: `/usr` is an erofs filesystem on a dm-verity protected partition, two slots (A/B); `/etc` is generated from `/usr/share/factory` + tmpfiles + confext; `/var` and `/home` are writable on an encrypted root.
- Consequences: atomic updates and rollback; integrity verification; package managers cannot modify the system at runtime (apps via Flatpak, extensions via sysext).

## ADR-0004 UEFI-first; legacy BIOS only as compat profile
- Context: systemd-boot and UKIs are UEFI-only; Secure Boot and measured boot need UEFI; Windows 11 requires UEFI.
- Decision: UEFI x86_64/aarch64 is the supported path. Legacy BIOS via GRUB in a separate "compat" profile without SB/measured boot (Phase 6).

## ADR-0005 Unified Kernel Images + systemd-boot + boot counting
- Decision: kernel + initrd + cmdline + os-release in one signed PE (UKI) built by ukify; systemd-boot with automatic boot assessment (`+3` tries) and `systemd-bless-boot`.
- Consequences: cmdline cannot be tampered with under Secure Boot; PCR 11 predictable → TPM policies survive updates when signed.

## ADR-0006 Secure Boot key strategy
- Decision: B2B fleets: enroll tenant PK/KEK/db (keeping Microsoft UEFI CAs in db) in firmware setup mode (systemd-boot `secure-boot-enroll` or our installer). Distributable/consumer images: Microsoft-signed shim from the base + tenant MOK enrolled once by user via MokManager.

## ADR-0007 Go for backend and agent; TypeScript/React for UI
- Decision: Go (static binaries, good for systems code, simple concurrency); React + Vite + TypeScript.
- Consequences: shared spec types generated from JSON Schema for both.

## ADR-0008 Postgres-backed job queue (River) instead of a separate workflow engine
- Context: Temporal/Kafka add operational load for a small team.
- Decision: River on Postgres + explicit build state machine table.
- Revisit when: > 50k builds/day or multi-step sagas across many services become painful.

## ADR-0009 Object storage with zero/low egress + CDN, content-addressed
- Decision: S3-compatible storage (e.g. Cloudflare R2 or self-hosted MinIO/Ceph), keys `sha256/<hex>`, immutable caching headers.

## ADR-0010 TUF for update metadata
- Decision: per-tenant TUF repository; device agent verifies metadata before handing files to systemd-sysupdate.
- Consequences: CDN and mirrors are untrusted; key roles with thresholds; freeze/rollback attacks detected.

## ADR-0011 Content-defined chunking for deltas (FastCDC)
- Decision: chunk the uncompressed usr image, seed from the device's current slot. Avoids per-pair binary diffs (O(releases²)).

## ADR-0012 Apps via Flatpak, OS extensions via systemd-sysext
- Decision: user-facing apps are Flatpaks from a per-tenant remote; OS-level additions are signed sysext images. No runtime `apt install` on devices.

## ADR-0013 Builds in ephemeral full VMs, not containers
- Context: mkosi needs loop devices, mounts and namespaces; customer scripts are untrusted.
- Decision: one KVM VM per build from a read-only golden image, destroyed after. Containers are not a security boundary here.

## ADR-0014 SAT-based option validation shared by client and server
- Decision: catalog compiled to one canonical CNF artifact; Web Worker and Go use it; server is authoritative.
