# Key management and key ceremony (Phase 0, P0-09)

## Decision
| Stage | Backend | Why |
|---|---|---|
| Phase 0–2 (dev, pilots) | Software keys in `signer` (`/var/lib/foundry/keys/<tenant>`, mode 0700, one host, no other service can read it) | Fast iteration; same code path as production behind the `Keys` operations |
| Phase 3+ (production) | Cloud HSM / KMS with a PKCS#11 module (non-exportable keys per tenant); YubiHSM2 for the offline platform root | Keys never leave hardware; per-tenant isolation; audit |

Only `cmd/signer` imports `internal/signer` (CLAUDE.md invariant 3). Every
signature is authorized against the database: the build must be `finalizing`
(i.e. approved), and inputs must be the build's recorded artifacts and verified
root hash. Each signature is written to the hash-chained audit log.

## Per-tenant keys (generated by `signer keys -tenant <org-slug>`)
| Key | Algorithm | Signs | Notes |
|---|---|---|---|
| PK | RSA-2048, self-signed | KEK updates | enrolled once (setup mode) |
| KEK | RSA-2048, signed by PK | db updates | |
| db | RSA-2048, signed by KEK | systemd-boot, UKIs, verity root hashes | the platform's *own* systemd-boot and stub are signed — never binaries from a build |
| pcr | RSA-2048 | TPM2 PCR 11 policy (`.pcrsig`), **initrd phase only** | disk keys can be unsealed in the initrd, never from the running system |
| artifact | Ed25519 | SHA256SUMS, manifests | devices/TUF verify downloads |

The Microsoft UEFI CA can be added to db (`FOUNDRY_SIGNER_EXTRA_DB_CERTS` or
`signer sign-image -extra-db`) so option ROMs and dual boot keep working on
real hardware.

## Offline platform root ceremony (production)
Participants: ceremony lead, two witnesses, recorder. Location: room without
network, camera recording on.
1. Boot the air-gapped laptop from a verified, read-only live medium; verify its hash aloud.
2. Initialize the YubiHSM2 (or HSM partition); generate the platform root keys (TUF root ×3, Ed25519; provenance root, ECDSA P-256) inside the HSM, non-exportable.
3. Back up the HSM wrap key with Shamir 3-of-5; each share printed and sealed in a tamper-evident bag, signed by both witnesses; bags go to five holders in two locations.
4. Sign the intermediate certificates / initial TUF root metadata (expiry 1 year). Export **public** material only to a fresh USB stick.
5. Record: date, participants, hashes of all exported files, HSM serials, bag numbers. Everyone signs the checklist.
6. Commit the public material to the repository (`deploy/keys/`), referencing the ceremony record.

## Rotation and compromise
- Rotation: db/pcr every 3–5 years (or on compromise); new UKIs are signed with both old and new PCR keys during the overlap so TPM policies keep unlocking; enrollment of a new db via KEK-signed update.
- Compromise of a tenant db key: revoke through dbx (KEK-signed), re-sign all releases with the new key, push update; devices re-enroll TPM policy on next boot.
- Compromise of the PCR key: devices that boot a UKI signed with an attacker's key would not unlock (policy bound to the public key), but an attacker with the key could sign one: rotate immediately and re-enroll TPM tokens via the agent.
